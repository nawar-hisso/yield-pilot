## 2. Page-by-Page Spec

### 2.1 Dashboard (`/`)

**Purpose.** Single-glance portfolio status — total value, P&L, APY trend, and live on-chain activity stream.

**Layout.**
```
┌─ Header (AppShell, sticky) ────────────────────────────────┐
├─ PageHeader: H1 "Dashboard" + muted subtitle ──────────────┤
├─ StatsRow: 3-col grid (md:grid-cols-3, gap-4) ─────────────┤
│   StatCard: Portfolio Value  │ StatCard: P&L  │ StatCard: APY │
├─ ChartSection: full-width card, tab switcher (7d/30d/90d) ─┤
│   Recharts AreaChart (P&L) + LineChart (APY) side-by-side  │
│   on desktop, stacked on mobile                            │
├─ ActivityFeed: card with scrollable list, WS-driven ───────┤
│   Each row: event icon + event type + address pill + time  │
└────────────────────────────────────────────────────────────┘
```

**Data sources.**

| Data | Source | Refresh |
|---|---|---|
| `totalAssets` (live TVL) | `useVault()` → `publicClient.readContract` via Multicall | 15 s SWR |
| Current user share balance | Extend `useVault()` with `balanceOf(address)` read | 15 s SWR |
| `totalDeposited`, `currentShares` | `lib/subgraph.ts` → `UserPosition` entity query | SWR on focus |
| P&L time-series (chart data) | Subgraph: `VaultDeposit` + `VaultWithdrawal` events per window | SWR on tab change |
| APY time-series | Subgraph: share price at T vs T-N derived from `convertToAssets` snapshots | SWR on tab change |
| Live activity feed | `useRealtime()` → `RealtimePayload` from `NEXT_PUBLIC_WS_URL` | Push (WebSocket) |

P&L computation: `currentValue = balanceOf(user) * convertToAssets(1e6) / 1e6` minus `totalDeposited` from subgraph. Both values in 6-decimal USDC units; format with `Intl.NumberFormat` (locale commas + "USDC" suffix).

**Interactions.** Dashboard is primarily read-only. "Connect wallet" CTA shown in stats area when `isConnected === false` (calls `connect()` from `useWeb3Auth()`).

**UI states.**

| State | Rendering |
|---|---|
| Loading | `Skeleton` placeholders shaped to `StatCard` height (h-16) and chart area (h-48) |
| Disconnected | Stats show `—`; chart renders with empty data + "Connect wallet to load your P&L" overlay |
| Empty (no deposits) | Activity feed: centered icon + "No activity yet. Deposit into the vault to get started." |
| Error (subgraph/RPC) | `StatCard` error badge: "Data unavailable" + retry icon; chart shows last cached data or empty |
| Live data | Stats populate; activity feed prepends new rows with fade-in `transition-all duration-200` |

### 2.2 Vault (`/vault`)

**Purpose.** Deposit USDC into the ERC-4626 vault, withdraw positions, and optionally execute gasless deposits via ERC-4337 Paymaster.

**Layout.**
```
┌─ PageHeader: "Vault" + vault address pill ─────────────────┐
├─ VaultStatsBar: 4-col (TVL | Share Price | APY | My Shares)┤
├─ ActionPanel: Tabs ["Deposit" | "Withdraw"] ───────────────┤
│   AmountInput (USDC, 6 dec) + preview line (shares/assets) │
│   GaslessToggle (switch) — only on Deposit tab             │
│   TxButton: "Deposit" / "Withdraw"                         │
│   TransactionStatus: inline pending / success / error      │
├─ HistoryTable: TxHash │ Type │ Assets │ Shares │ Time ──────┤
│   Data from subgraph VaultDeposit + VaultWithdrawal        │
│   Paginated (10 rows), horizontally scrollable on mobile   │
└────────────────────────────────────────────────────────────┘
```

**Data sources.**

| Data | Source |
|---|---|
| TVL, share price | `useVault()` — `totalAssets()` + `convertToAssets(parseUnits("1","6"))` |
| My share balance | Extend `useVault()` with `balanceOf(address)` |
| Preview shares on input | `publicClient.readContract({ functionName: "convertToShares", args: [assets] })` on debounced input |
| Preview assets on withdraw input | `publicClient.readContract({ functionName: "convertToAssets", args: [shares] })` |
| Tx history | `lib/subgraph.ts` — query `VaultDeposit` + `VaultWithdrawal` filtered by `user` |

**Interactions — wagmi/viem calls.**

Deposit (standard):
```ts
useWriteContract({
  abi: YieldVaultAbi,
  address: VAULT_ADDRESS,
  functionName: "deposit",
  args: [assets, receiver],   // assets: bigint (6 dec), receiver: address
})
```

Withdraw:
```ts
useWriteContract({
  abi: YieldVaultAbi,
  address: VAULT_ADDRESS,
  functionName: "withdraw",
  args: [assets, receiver, owner],
})
```

Gasless deposit (ERC-4337 path, Phase 5): Build a `UserOperation` for `deposit(assets, receiver)`, sponsor via `Paymaster.sol`, submit to bundler endpoint (`NEXT_PUBLIC_BUNDLER_URL`). Use `walletClient` from `useSigner()` to sign the user op. Gasless toggle is a shadcn `Switch`; when enabled, the deposit button label becomes "Gasless Deposit" and bypasses direct `useWriteContract`.

USDC approval check: before deposit, read `MockUSDC.allowance(owner, VAULT_ADDRESS)`; if below `assets`, show "Approve USDC" as the first step of a two-step `TxButton`.

**UI states.**

| State | Rendering |
|---|---|
| Input empty | TxButton disabled, no preview |
| Input > balance | TxButton disabled, red helper "Insufficient balance" |
| Preview loading | Skeleton pill next to input |
| Confirming (wallet open) | TxButton shows spinner + "Confirm in wallet…"; input + toggle disabled |
| Pending (tx submitted) | `TransactionToast` bottom-right: spinner + truncated tx hash + Sepolia Etherscan link |
| Success | Toast: checkmark + "Deposited X USDC"; SWR cache mutated; history table row prepended |
| Error | Toast: destructive + error message + "Retry" button |
| Disconnected | Action panel replaced with centered `ConnectButton` CTA |

### 2.3 Delegate (`/delegate`)


**Layout.**
```
┌─ PageHeader: "Delegate" + Safe address pill (if exists) ───┐
├─ SafeStatusCard: Safe address │ owners │ threshold ─────────┤
│   "Create Safe" button when no Safe detected               │
│   Columns: Address │ Added At │ Actions (Remove)            │
│   "+ Add Operator" button → Dialog (address input + TxBtn) │
│   "Attach Guard" button if not yet attached                 │
│   Columns: Operator │ Target │ Action │ Time │ TxHash       │
└────────────────────────────────────────────────────────────┘
```

**Data sources.**

| Data | Source |
|---|---|
| Safe address for connected wallet | `lib/api.ts` → `GET /user/safe?address=0x…` (stored in DB post-creation) or on-chain Safe factory lookup |
| Safe owners, threshold | Safe SDK `getSafeInfo()` using `publicClient` + Safe contract address |

**Interactions.**

Create Safe: Safe SDK `createSafe({ owners: [address], threshold: 1 })`, then persist address via `lib/api.ts` → `PUT /user/preferences` with `safeAddress`.

Add operator:
```ts
useWriteContract({
  address: MODULE_ADDRESS,
  functionName: "addOperator",
  args: [operatorAddress],
})
```

Remove operator: same ABI, `functionName: "removeOperator"`.

Attach guard:
```ts
useWriteContract({
  address: safeAddress,
  functionName: "setGuard",
})
```

**UI states.** No Safe: "Create Safe" primary CTA, operator list and guard sections hidden. Safe loading: `Skeleton` for address pill and operator table. Error fetching operators: inline error badge with retry.

### 2.4 Multi-sig (`/multisig`)

**Purpose.** Approve, sign, or reject pending Safe transactions for team-managed vaults (2-of-N threshold).

**Layout.**
```
┌─ PageHeader: "Multi-sig" + threshold badge ("2 of 3") ─────┐
├─ PendingTxList: card per pending tx ────────────────────────┤
│   Each card: tx hash | target | calldata summary | sigs     │
│   "Sign" + "Reject" buttons; "Execute" if threshold met     │
└────────────────────────────────────────────────────────────┘
```

**Data sources.** Safe SDK `getPendingTransactions(safeAddress)` (Safe Transaction Service API). Signatures: `safeApiKit.confirmTransaction(txHash, signature)`.

**UI states.** No pending txs: empty state "No pending transactions". Not a Safe owner: read-only view showing pending queue with no action buttons. Disconnected: wallet CTA.

### 2.5 Settings (`/settings`)

**Purpose.** Toggle notification preferences (stored in PostgreSQL), switch active chain, and manage the connected Web3Auth account.

**Layout.**
```
┌─ PageHeader: "Settings" ───────────────────────────────────┐
├─ NotificationsCard ─────────────────────────────────────────┤
│   Switch: "Notify on deposits"                              │
│   Switch: "Notify on withdrawals"                          │
│   "Save preferences" button → PUT /user/preferences        │
├─ NetworkCard ───────────────────────────────────────────────┤
│   SegmentedControl: Sepolia | Base Sepolia                  │
│   On switch: update NEXT_PUBLIC_CHAIN_ID via query param    │
│   or re-init Web3Auth with new chain config                 │
├─ AccountCard ───────────────────────────────────────────────┤
│   Address pill (copyable) + "Disconnect" button             │
│   Web3Auth social login method shown (Google / X / Email)  │
└────────────────────────────────────────────────────────────┘
```

**Data sources.** `lib/api.ts` → `GET /user/preferences` (SWR, keyed by `address`). `PUT /user/preferences` on save. Chain preference persisted server-side; client reads `NEXT_PUBLIC_CHAIN_ID` at boot.

**UI states.** Loading: `Skeleton` for each switch row. Save in-flight: "Save preferences" button shows spinner. Error: destructive toast. Success: "Preferences saved" success toast.

## 4. Design Tokens

All components use CSS variable-backed Tailwind classes. Never reach for `brand.primary` or `brand.accent` hex directly in component JSX — those keys in `tailwind.config.ts` exist only as reference values for tooling (Figma tokens, Storybook). Runtime theming always goes through `hsl(var(--…))`.

| Semantic token | Tailwind class | Dark mode value (hsl) | Use |
|---|---|---|---|
| Page background | `bg-background` | 218 67% 9% | Body, main |
| Card surface | `bg-card` | 218 67% 11% | StatCard, panels |
| Primary action | `bg-primary text-primary-foreground` | accent cyan in dark | Deposit / CTA buttons |
| Accent highlight | `text-accent` / `border-accent` | 187 85% 53% | Active nav, focus ring |
| Subtle text | `text-muted-foreground` | 220 9% 66% | Labels, placeholders |
| Danger | `bg-destructive text-destructive-foreground` | 0 63% 42% | Error toasts, reject |
| Border | `border-border` | 218 40% 20% | Card outlines, dividers |
| Input | `bg-input` / `border-input` | 218 40% 20% | AmountInput, form fields |
| Focus ring | `ring-ring` | accent cyan | Focus-visible outlines |

`--radius: 0.5rem` applied via `rounded-lg` (0.5 rem), `rounded-md` (0.375 rem), `rounded-sm` (0.25 rem).

The cyan `#22D3EE` on midnight-blue `#0B1E3B` background achieves a contrast ratio of ~8.5:1, passing WCAG AA at all text sizes and AAA for large text (18pt+). The same pair in dark mode (accent on card) passes AA at normal sizes.


```
Axes:
```

## 6. Real-time UX

`hooks/useRealtime.ts` opens one `WebSocket` to `NEXT_PUBLIC_WS_URL` (the `apps/api` ws server at `apps/api/src/ws/server.ts`). The hook exposes `{ last: RealtimePayload | null }`.

**ActivityFeed.** Maintains a local `events: VaultEvent[]` array via `useReducer`. On each `last` change matching `type === "vault.event"` or `type === "safe.action"`, prepend to the array (cap at 50 entries). Each row renders with a fade-in `transition-all duration-200 animate-in slide-in-from-top-1`.

**Toast notifications.** A separate `useEffect` in `ActivityFeed` (or a top-level `EventNotifier` mounted in `Providers.tsx`) watches `last`; on new `vault.event` matching the connected `address`, fire a shadcn `toast({ title: "Deposit confirmed", description: "X USDC" })`.

**Connection indicator.** `ChainStatus.tsx` reads `ws.readyState` via a ref forwarded from `useRealtime`. Green dot when `OPEN`, amber dot with "Reconnecting…" when `CONNECTING`, red dot when `CLOSED`. On `CLOSED`, the hook re-attempts after a 3-second delay (add `reconnectTimeout` ref to `useRealtime`).

**Ping keepalive.** `type === "ping"` payloads are silently consumed (no state update, no render). This prevents the WS from being dropped by idle-timeout proxies.

## 7. Forms and Validation

### AmountInput (`components/shared/AmountInput.tsx`)

- `type="text"` (not `number`) to preserve decimal control.
- Parse with `parseUnits(value, 6)` from viem for MockUSDC (6 decimals). Reject non-numeric input at `onChange`.
- Show preview below input: "≈ {shares} YP shares" (Deposit) or "≈ {assets} USDC" (Withdraw), fetched on 400 ms debounced input via `publicClient.readContract({ functionName: "convertToShares" | "convertToAssets" })`.
- Disable submit conditions: empty, parse error, value > balance, pending approval, tx in-flight.
- Max button: fills input with full balance (`formatUnits(balance, 6)`).

### Gasless toggle copy

Switch label: "Gasless deposit (sponsored)". Tooltip (shadcn `Tooltip`): "Gas fees are covered by YieldPilot's Paymaster. Your wallet signs a UserOperation instead of a standard transaction."

### Approval flow (two-step TxButton)

Step 1 label: "Approve USDC" — calls `MockUSDC.approve(VAULT_ADDRESS, assets)`.
Step 2 label: "Deposit" — enabled only after approval confirmed (watch `useWaitForTransactionReceipt`).
A `Steps` indicator (two dots with connector line) shows progress above the button.

## 8. Accessibility

- All `<button>` elements have explicit `aria-label` when they contain only icons (e.g. `aria-label="Copy address"`, `aria-label="Disconnect wallet"`).
- `ConnectButton` (`AppShell.tsx`) exposes `aria-expanded` on the dropdown (when implementing the full dropdown with copy/explorer).
- `AmountInput` links its preview text via `aria-describedby="preview-{id}"`.
- Focus states: all interactive elements have `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`. Never remove `outline` without a visible replacement.
- Chart containers have `role="img"` and `aria-label="P&L chart for the last 30 days"`.
- `TransactionToast` uses `role="status"` with `aria-live="polite"` for success; `role="alert"` with `aria-live="assertive"` for errors.
- Skeleton loaders have `aria-busy="true"` on their container and `aria-label="Loading…"`.

## 10. Shadcn/ui Components to Install

The scaffold does not yet have a `components.json` (shadcn CLI config). **Phase 3 setup step**: run `npx shadcn@latest init` inside `apps/web`, choose the "New York" style with CSS variables, then install:

```bash
npx shadcn@latest add button card input dialog table toast skeleton tabs switch tooltip sheet
```

| Component | Used in |

| `dialog` | AddOperatorDialog, confirm dialogs |

All components are customised via `cn()` from `lib/utils.ts` — no overrides to the shadcn source files.
